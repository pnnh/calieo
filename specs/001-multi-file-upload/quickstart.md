# 快速验证指南：批量文件上传与同目录自动重命名

**功能**: [spec.md](./spec.md) | **契约**: [contracts/upload-api.md](./contracts/upload-api.md) | **数据模型**: [data-model.md](./data-model.md)

## 前置条件

- 已安装依赖：`pnpm install`
- 本地数据库已迁移：`pnpm run db:migrate`
- 已有一个可登录的测试用户（沿用现有登录/鉴权流程，不在本次功能范围内）

## 启动开发环境

```bash
pnpm dev
```

浏览器访问 `http://localhost:7300/en/console/files/new`（可先在 `/en/console/files` 下进入某个目录，再点击"新建/上传"进入该目录下的上传页面，以便验证 `parentId` 相关场景）。

## 手动验证场景（对应 spec.md 中的 Acceptance Scenarios）

1. **正常批量上传**：选择 2-20 个互不重名的文件并提交，确认全部文件出现在目标目录的文件列表中，且页面展示每个文件的处理结果为"成功"。
2. **数量超限**：尝试一次性选择 21 个及以上文件，确认提交按钮点击后（或选择文件时）立即提示"单次最多选择 20 个文件"，且未发起网络请求（可通过浏览器开发者工具的网络面板确认无请求）。
3. **总大小超限**：选择数量 ≤20 但总大小超过 300 MB 的文件组合，确认提交前被阻止并提示"批次总大小不能超过 300 MB"。
4. **单文件超限**：批次中包含一个超过 20 MB 的文件与若干正常文件，提交后确认超限文件的结果显示为失败并说明原因，其余文件仍成功创建。
5. **同目录重名自动重命名**：目标目录下已存在 `report.pdf`，上传另一个同名 `report.pdf`，确认新文件被创建且文件名带有随机后缀、扩展名仍为 `.pdf`；原文件不受影响。
6. **批次内重名自动重命名**：同一次选择两个文件名完全相同的文件（目标目录下均无同名文件），提交后确认其中一个保留原名，另一个自动重命名，两者都成功创建。
7. **单文件上传兼容性**：仅选择 1 个文件提交，确认行为与调整前的单文件上传一致。

## 自动化验证

```bash
# 组件与单元测试（包含 FileUploadForm 相关用例）
pnpm test

# 端到端测试（如新增/调整了相关 e2e 场景）
pnpm run test:e2e
```

验证要点：

- `src/components/FileUploadForm.test.tsx` 覆盖：`multiple` 选择、数量/总大小/单文件大小的前置校验提示、提交后逐文件结果展示。
- 上传路由的测试覆盖 [contracts/upload-api.md](./contracts/upload-api.md) 中定义的批次级前置校验（400/404 场景）与单文件级 continue-on-error 处理（`results` 数组中 `created` / `renamed` / `failed` 的分布）。

## 回归检查

- 确认现有单文件上传相关测试与端到端用例仍然通过，未因本次调整而被破坏。
- 确认生产部署路径（Cloudflare D1 + R2）与本地开发路径（SQLite + 本地文件系统）在上述场景下行为一致（可通过 `wrangler`/OpenNext 的本地模拟环境或部署到预览环境验证，具体步骤沿用仓库现有的部署流程，不在本文档展开）。
